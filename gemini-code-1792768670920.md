# Automated Web Security Scanner: Secure Headers & CORS Audit Framework

An automated, non-invasive Python security auditing tool that assesses web applications for missing or weak HTTP security headers and tests for common Cross-Origin Resource Sharing (CORS) misconfigurations.

---

## 📌 Project Overview
Modern web security heavily relies on browser-enforced security mechanisms. When servers omit protective HTTP response headers or misconfigure CORS rules, client browsers cannot defend users against attacks such as Cross-Site Scripting (XSS), Clickjacking, or unauthorized cross-origin data theft.

This scanner performs automated audits by:
- Verifying the presence and directive strength of 6 critical HTTP defensive headers.
- Flagging information disclosure headers (`Server`, `X-Powered-By`).
- Probing CORS handling with 4 distinct test origins (arbitrary reflection, null origin, prefix, and suffix bypasses).
- Calculating an aggregate security posture score (0–100) and assigning a letter grade (A+ through F).
- Exporting audit results to structured JSON and terminal tables.

---

## 🚀 Features & Audit Coverage

### 1. Defensive Header Inspection
- **Strict-Transport-Security (HSTS):** Checks for `max-age` (>= 31536000 seconds) and `includeSubDomains`.
- **Content-Security-Policy (CSP):** Flags missing policy and unsafe directives (`'unsafe-inline'`, `'unsafe-eval'`).
- **X-Frame-Options:** Validates protection against Clickjacking (`DENY` or `SAMEORIGIN`).
- **X-Content-Type-Options:** Confirms `nosniff` enforcement against MIME-sniffing.
- **Referrer-Policy:** Audits leakage of referrer paths and tokens.
- **Permissions-Policy:** Checks for browser API delegation controls (camera, microphone, geolocation).

### 2. CORS Misconfiguration Probing
- **Arbitrary Origin Reflection:** Detects whether untrusted origins are reflected alongside `Access-Control-Allow-Credentials: true`.
- **Null Origin Exploitation:** Checks whether `Origin: null` is accepted, which exposes sites to sandboxed iframe attacks.
- **Subdomain / Regex Confusion:** Probes for unanchored whitelist validation (`domain.attacker.com` and `attacker-domain.com`).
